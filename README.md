# OLLM — OneGodian LLM

OLLM is the OneGodian multi-model intelligence orchestration product and governed synthesis runtime for the OneGodian ecosystem.

## Canonical Product Architecture

- **Marketing:** `https://onegodian.org/ollm`
- **Application:** `https://llm.onegodian.org`
- **Core repository:** `ohi-stack/onegodian-llm`
- **Governance/runtime integration:** OHI / QOHI control-plane services

## Product Objective

OLLM is being upgraded from an internal architecture repository into a production software product. The production user journey is:

1. Visitor discovers OLLM through `onegodian.org/ollm`.
2. User creates an account or signs in.
3. User enters the OLLM dashboard at `llm.onegodian.org`.
4. User submits a prompt and selects available model providers.
5. OLLM collects provider outputs.
6. OHI governance compares, filters, normalizes, and synthesizes the result.
7. The governed output is returned with execution metadata.
8. The session is persisted to user history.
9. Usage is metered for subscription and business plans.

## Governance

OHI™ means OneGodian Hyper-Conscious Intelligence™.

QOHI™ means Quantum-OHI™, an advanced verification, forecasting, and high-complexity execution layer used only where approved by scope, policy, and human authority.

The OLLM runtime must preserve human final authority. Raw model outputs are not treated as authoritative merely because they were generated by a model. OLLM's governing workflow is:

`prompt → provider outputs → compare → filter → normalize → governed output`

This repository uses technical terms such as provider, worker, service, workflow, and runtime for software components. Where legacy code uses `agent` as an implementation term, it does not imply independent authority or substitution for human decision-making.

## Production Definition of Done

OLLM may be described as **v1.0 Production** only when all of the following are operational, documented, and repeatable:

- authenticated application at `llm.onegodian.org`
- email and Google sign-in
- functioning dashboard
- live model-provider execution
- governed multi-model synthesis
- persistence/history
- usage metering
- paid subscription pathway
- security and entitlement controls
- structured error handling and logging
- health monitoring
- production deployment procedure
- rollback procedure
- build/typecheck passing in CI
- operator documentation

Until those conditions are satisfied, the product status remains pre-production, beta, release-candidate, or launch-in-progress as appropriate.
